## Representation rule

These entries are **context**, not technical-certification claims.

The repository should continue to make concrete engineering claims only where there is code, tests, documentation, or another directly inspectable artifact supporting the claim.

The external profile can therefore be used to explain:

1. the broader developer ecosystem around the project;
2. current learning and platform exposure;
3. community participation;
4. why AI, cloud security, threat intelligence and agent-security concerns are represented in the WarRoom.

It should not be used as a substitute for repository evidence.

## UI principle

If this information is surfaced inside the WarRoom, it should appear as a **Developer Ecosystem / Operator Context** panel with links and short descriptions, not as achievement badges.
